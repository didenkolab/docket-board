The board pushed for months and never looked at what had arrived. A vault is a repository, so
the other ways in are ordinary — Obsidian on another machine, a merged proposal, an agent in a
clone — and the board drew a board that was out of date with nothing to say so.

A fetch on the same timer as every other question to a host, a ↓ beside the ↑, and a button that
fast-forwards. Only fast-forward: joining two plans is a decision, and this one would be made
against a working tree somebody may have open.

And a change made while a push was in flight used to be dropped. Because `git push` sends every
commit on the branch the next write usually carried it along, and usually is the failure: drag
three cards quickly and the last commit sat in the folder with the board reporting nothing
wrong. It asks git what is left and goes round again — the count knows about commits the board
never made, which a flag could not.
